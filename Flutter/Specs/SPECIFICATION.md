# Спецификация приложения LocalTube (MAUI)

## 1. Назначение
LocalTube — клиентское приложение для персональной видеотеки, которое позволяет:
- авторизоваться в серверном API;
- просматривать списки видео (история, новинки, последние, по сериалам/сезонам, по плейлистам);
- воспроизводить видео с позиции продолжения;
- скачивать видео для офлайн-просмотра и управлять локально сохраненными файлами;
- ставить закладки по времени и быстро переходить по таймкодам из описания;
- синхронизировать воспроизведение между подключенными клиентами.

Основная ценность: единый мобильный/десктопный клиент для просмотра контента с сервера с офлайн-кэшем и продолжением просмотра.

## 2. Область применения
Приложение рассчитано на пользователя, у которого есть доступ к серверу LocalTube API.
Поддерживаемые платформы в проекте: Android и Windows (.NET MAUI, net8.0).

## 3. Архитектура (кратко)
- UI: .NET MAUI (XAML + MVVM, CommunityToolkit.Mvvm).
- Навигация: Shell + маршруты страниц.
- API-интеграция: `HttpClientAuth` + `APIService`.
- Локальное хранение метаданных/путей: SQLite через инфраструктурные репозитории (`FileStore.*`).
- Плеер: `CommunityToolkit.Maui.MediaElement`.
- Фоновые загрузки:
  - Android: `Shiny.Net.Http`;
  - Windows: `WebClient`.
- Логирование: MetroLog (debug/console/in-memory/file).
- Межклиентская синхронизация плеера: SignalR (`/player`).

## 4. Ключевые функции

### 4.1 Авторизация
- Вход по логину/паролю.
- Сохранение токенов и учетных данных в `SecureStorage`.
- Попытка авто-входа при открытии экрана логина.
- Авто-обновление токена; при невозможности обновления — очистка токенов и переход на логин.

### 4.2 Каталоги и фильтры
С главного экрана доступны разделы:
- скачанные видео;
- новинки;
- последнее видео;
- история (последние N);
- сериалы/сезоны;
- экран активных загрузок;
- просмотр логов;
- выход из аккаунта.

### 4.3 Список видео
Для элементов списка доступны действия:
- открыть видео в плеере;
- скачать видео;
- удалить локально скачанный файл;
- удалить видео на сервере;
- добавить видео в плейлист;
- создать новый плейлист;
- массово скачать Top-N из текущего списка.

### 4.4 Плеер
Возможности плеера:
- воспроизведение онлайн (URL сервера) или локального файла (если скачан);
- автоматическое восстановление позиции просмотра из локальной БД и сервера;
- периодическая синхронизация текущей позиции (локально + на сервер);
- переход по таймкодам из описания;
- переход к следующему «ближайшему» таймкоду из описания;
- открытие списка файлов сезона текущего видео;
- удаление видео (локально/на сервере), перезапуск с начала.

### 4.5 Закладки
- Ручное добавление закладки на текущей позиции.
- Авто-добавление закладки при короткой паузе/возобновлении.
- Удаление закладки.
- Повторная отправка на сервер локально накопленных, но неотправленных закладок.

### 4.6 Офлайн и загрузки
- Скачивание видео в `AppDataDirectory`.
- Проверка факта скачивания при построении списков.
- Просмотр ранее скачанных файлов без сети.
- Экран мониторинга активных загрузок и возможность остановки.

### 4.7 Межклиентская синхронизация
- Подключение к SignalR-хабу плеера.
- Получение списка подключенных клиентов.
- Отправка команды воспроизведения на выбранный клиент с передачей `videoId` и позиции.
- Получение команды `PlayOnClient` и запуск указанного видео на принимающем клиенте.

## 5. Интеграционные точки (API)
Используются основные группы endpoint'ов:
- `account/*` (login, refresh-token);
- `files/*` (списки, файл по id, обложка, позиция, удаление);
- `series/*`;
- `playlists/*`;
- `marks/*`.

Базовый URL (по коду):
- `https://api.example.invalid:9999`
- API префикс: `/api/`
- SignalR: `/player`

## 6. Нефункциональные требования (по текущей реализации)
- Приложение должно работать при нестабильной сети: сетевые ошибки в API обрабатываются возвратом пустых коллекций/без падения UI.
- Данные авторизации и токены хранятся в защищенном хранилище платформы (`SecureStorage`).
- Логи ошибок пишутся в память и файлы (кэш приложения, с ротацией).
- Для офлайн-воспроизведения должен использоваться локальный путь файла, если файл скачан.

## 7. Ограничения текущей реализации
- Shell стартует только с `LoginPage`; табы/разделы реализованы через переходы по маршрутам.
- Экран загрузок использует `Shiny.NET.MainPage` и выглядит как сервисный экран мониторинга.
- Часть действий в UI зависит от наличия интернета; в debug часть ограничений отключена.
- Есть блоки `try/catch` без явной обработки ошибок, поэтому часть проблем может оставаться только в логах.

## 8. Основные пользовательские сценарии
1. Пользователь входит в аккаунт и открывает «Новинки».
2. Выбирает видео, запускает просмотр, позже продолжает с сохраненной позиции.
3. Добавляет закладку и переходит по таймкоду из описания.
4. Скачивает видео и смотрит его офлайн в разделе «Скачанное».
5. Добавляет видео в плейлист или создает новый плейлист.
6. При необходимости отправляет текущее видео на другой подключенный клиент.

## 9. Результат
LocalTube решает задачу персонального просмотра видеокаталога с единым аккаунтом, продолжением просмотра, закладками, плейлистами, офлайн-доступом и межклиентской синхронизацией воспроизведения.
